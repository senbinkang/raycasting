# 2026-06-17 — 7 个 Bug 根因分析

## 一、背景

用户反馈 7 个问题，逐项阅读全部源码后分析如下。

## 二、逐项根因

### Bug 1：人物和敌人都能穿墙

**玩家侧**（`Player.js:127-151` `tryMove()`）：

- `collisionRadius = 0.2`（格子宽度 1.0），碰撞圆太小
- 分轴检测只检查单个点 `(checkX, position.y)` 和 `(position.x, checkY)`，不覆盖整个碰撞圆
- 当 deltaTime 较大或处于冲刺状态（`moveSpeed = 4.5`），单帧步长可达 0.2~0.25 格，足以一步跨过碰撞检测边界
- `_collidesBlockingSprite`（第 179-190 行）只做精灵阻挡，不增强墙体检测

**敌人侧**（`Sprite.js:84-100` `update()`）：

- 第 85-88 行：`Math.floor(moveX)` 直接判断格子是否为空，完全没用 `this.radius`
- 敌人被视为一个无限小的点——视觉上是半径 0.2 的圆，但碰撞上是零半径
- 所以敌人可以把半个身子"嵌"进墙里，视觉上穿墙

**修复方向**：增大 collisionRadius 到 0.3~0.4；敌人 side 检测也加上 radius 偏移（参考玩家 `tryMove` 的 checkX/checkY 逻辑）。

### Bug 2：两块红墙之间被卡住

**根因**（`Player.js:127-151`）：

分轴碰撞先尝试 X 轴、再尝试 Y 轴。进入墙角时（如 (0.85, 1.5) 靠近左侧红墙 x=0）：

- X 轴被墙挡住，不移动
- Y 轴尝试移动，但 `cellIsEmpty(this.position.x, checkY)` 中 `this.position.x = 0.85`，`Math.floor(0.85) = 0`，而 `worldMap[checkY格][0] = 1`（红墙），Y 轴也被挡住
- 玩家被"夹"在墙角，两轴都拒绝移动

实际上这反映了**碰撞半径太小 + 单点检测**在墙角几何下的固有问题：玩家可以走到离墙 0.2 格以内，此时无论朝哪个方向移动，check 点都会落入墙格。

**修复方向**：增大 `collisionRadius` 到 0.35~0.4，让玩家在离墙更远的地方就被挡住，不会走到墙角死角里。

---

### Bug 3：敌人卡在玩家前面，无法前进

`Player.js:179-190` `_collidesBlockingSprite()`：

- 敌人 `isBlocking = true`（`Sprite.js:35`），所以玩家会被敌人挡住
- 敌人 AI（`Sprite.js:78`）在距离 `(radius + player.collisionRadius) * 1.01 ≈ 0.4` 时停止移动
- 此时玩家被 ~0.4 格外的敌人完全阻挡，无法从任何方向绕过去

**修复方向**：
- 方案 A：敌人不阻挡玩家（`isBlocking = false`），只做伤害接触
- 方案 B：加"推开"机制——当玩家朝敌人方向移动时，把敌人推开
- 方案 C：增大敌人保持距离（如 1.0 格），让玩家有绕行空间

---

### Bug 4：射击无效

`Weapon.js:36-108` `fire()`：

1. **命中判定公式错误**（第 102 行）：
   ```
   Math.abs(tx - ty * (screenX - player.position.x) / player.dirX) < hitRange
   ```
   `tx`/`ty` 是相机空间坐标，`player.position.x` 是世界坐标，两者做减法无数学意义。正确做法是判断 sprite 的屏幕 X 坐标是否在准星（屏幕中央）附近。

2. **冷却永不设置**：`fire()` 开头 `if (this.cooldown > 0) return null`，但 fire() 内部从不设置 `this.cooldown = this.cooldownTime`。冷却永远为 0，虽然不影响"能开火"但意味着每帧都在判定（也不设置后坐力/音效）。

3. **后坐力不触发**：`fire()` 不设置 `this.recoil = 1`。

4. **射击音效不触发**：`playShoot()` 没有在任何地方被调用。

5. **DDA 射线没有限制射程**：射线一直走到地图边界或撞墙，合理但应该加最大射程（如 10 格）。

**正确命中判定逻辑**：
- 对每个活着的敌人，将其位置变换到屏幕空间
- 判断 sprite 的屏幕 X 范围是否覆盖屏幕中心（准星位置）
- 判断 sprite 的深度是否在合理范围（且在墙之前，即 < zBuffer[screenCenterX]）

---

### Bug 5：医疗包没有实际效果

`Player.js:193-205` `pickupItems()`：

```javascript
if (dx * dx + dy * dy < pickRadius * pickRadius) {
    s.alive = false
    // 这里可以播放音效等（后续阶段 GL 再实现）
}
```

只让物品消失，不回复玩家 HP。注释也确认了这是未完成的功能。

**修复方向**：加 `this.hp = Math.min(this.maxHp, this.hp + 30)`。

---

### Bug 6：没有血条

`Game.js:153-183` `drawHUD()` 只绘制 FPS、位置、朝向和操作提示。Player 虽有 `hp=100 / maxHp=100` 但完全不显示。

**修复方向**：在 HUD 区域的左下角或顶部绘制血条（红底 + 绿色/红色填充 + 数值文字）。

---

### Bug 7：缺少开始/结束画面

`index.js` 中 `__main()` 直接启动游戏，无状态机。

**修复方向**：
- 引入游戏状态：`menu` / `playing` / `gameover` / `win`
- `menu`：标题 + "开始游戏"按钮
- `gameover`：玩家 HP ≤ 0 时触发，"你死了" + "重新开始"按钮
- `win`：所有敌人死亡时触发，"通关" + "重新开始"按钮
