# AI 实时解说 — 研究

> 2026-07-07

## 一、现有架构分析

### 1.1 游戏事件流

所有游戏逻辑集中在两个文件的 update 方法中：

**GameScene.update(dt)** — 核心事件点：
- 精灵 AI 更新 + 敌人生成子弹 → `spriteManager.update()`
- 敌方子弹飞行/碰墙/碰玩家
- 武器后坐力更新 → `weapon.update(dt)`
- 玩家无敌计时器更新
- 波次提示计时器更新
- 脚步声更新
- 玩家死亡检测 → state = 'gameover'
- 敌人全灭检测 → `_respawnEnemies()`（波次+1 或胜利）

**Game.update()** — 射击触发点：
- 玩家射击 → `weapon.fire()` → 命中判定 → 扣血/死亡/加分
- 暂停切换

### 1.2 可解说的事件清单

| 事件 | 触发位置 | 关键上下文 |
|------|---------|-----------|
| 游戏开始 | `GameScene.startGame()` | state: menu → playing |
| 新波次 | `GameScene._respawnEnemies()` | wave 编号, 敌人数 |
| 通关胜利 | `GameScene._respawnEnemies()` wave>=5 | score, highScore |
| 玩家死亡 | `GameScene.update()` hp<=0 | score, wave, highScore |
| 玩家受伤 | `Player.takeDamage()` | 剩余 HP, 伤害值 |
| 击杀敌人 | `Game.update()` 射击命中+死亡 | 敌人类型, 剩余敌人数, 得分 |
| 敌人受伤 | `Game.update()` 射击命中未死 | 敌人类型 |
| 敌方子弹命中 | `GameScene.update()` 子弹碰玩家 | 剩余 HP |
| 拾取医疗包 | `Player.pickupItems()` | 回复量, 当前 HP |
| 低血量警告 | 需新增检测 | HP 阈值 |
| 破纪录 | `GameScene._checkHighScore()` | 新纪录分数 |
| 暂停/继续 | `Game.update()` P 键 | paused 状态 |
| 波次清空 | `GameScene.update()` 敌全灭 | 即将进入下一波 |

### 1.3 音效系统现状

AudioManager.js 使用 Web Audio API 程序化合成，不依赖音频文件。AI 解说需要的是 TTS（文字转语音），与现有音效系统是互补关系，不是替代关系。

## 二、TTS 方案

### 方案 A：Web Speech API（推荐）

浏览器内置 `SpeechSynthesis` API，零依赖。

```js
const utter = new SpeechSynthesisUtterance('第一波敌人出现了！')
utter.lang = 'zh-CN'
utter.rate = 1.0
utter.pitch = 1.0
speechSynthesis.speak(utter)
```

**优点**：零依赖、零延迟、离线可用、免费
**缺点**：声音较机械（取决于系统和浏览器），不同 OS/浏览器语音质量差异大
**macOS**：Tingting（中文女声），质量较好
**Windows**：Microsoft Huihui（中文女声），质量一般
**Chrome**：Google 中文语音，质量较好

### 方案 B：云端 TTS API

调用第三方 TTS API（如 Azure TTS、百度语音等），音质更好但增加延迟和依赖。

**建议**：先用方案 A 实现，后续可替换为云端 TTS。

## 三、LLM 解说文本生成方案

### 3.1 核心问题：API Key 怎么办

当前项目是纯前端，没有后端。直接在前端调用 LLM API 会暴露 Key。

**选项 1：用户自行配置 API Key**
- 在暂停菜单或设置区加一个输入框，用户填入自己的 API Key + Endpoint
- 存入 localStorage
- 支持 OpenAI 兼容接口（包括各种代理/中转）

**选项 2：模板为主 + LLM 增强**
- 高频事件（击杀、受伤）用预写模板
- 低频重要事件（波次切换、胜利、死亡）调 LLM
- 减少 API 调用量和延迟

**选项 3：纯模板系统（无 LLM）**
- 完全不用 API，写丰富的解说词模板
- 零成本、零延迟、零配置
- 缺点是缺乏变化，不够"AI"

### 3.2 推荐：选项 1 + 2 混合

```
模板层（基础） → LLM 增强层（可选）
     ↓                    ↓
 高频事件即时播报     重要事件 AI 生成
 （击杀/受伤等）      （波次/胜负点评）
```

用户不配 Key 也能用（模板模式），配了 Key 后有 AI 点评增强。

### 3.3 LLM API 调用设计

```js
// CommentaryService 核心接口
async function generateCommentary(event) {
    const config = loadConfig()  // 从 localStorage 读取
    if (!config.apiKey) return getTemplate(event)  // 降级到模板

    const prompt = buildPrompt(event)  // 构建 prompt
    const response = await fetch(config.endpoint, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${config.apiKey}`
        },
        body: JSON.stringify({
            model: config.model || 'gpt-3.5-turbo',
            messages: [
                { role: 'system', content: SYSTEM_PROMPT },
                { role: 'user', content: prompt }
            ],
            max_tokens: 80,
            temperature: 0.9
        })
    })
    const data = await response.json()
    return data.choices[0].message.content
}
```

**Prompt 设计要点**：
- System prompt 定义解说风格（电竞解说员 / 冷静分析 / 幽默风趣）
- User prompt 精简到只含关键游戏状态
- max_tokens 限制在 80 以内（解说应该短小精悍）
- 要求返回纯文本，不超过 2 句话

## 四、解说触发策略

### 4.1 频率控制

需要冷却机制防止事件风暴：

| 事件类型 | 优先级 | 冷却时间 | 可插队 |
|---------|--------|---------|--------|
| 玩家死亡 | 最高 | 无冷却 | 是 |
| 通关胜利 | 最高 | 无冷却 | 是 |
| 新波次 | 高 | 5s | 是 |
| 破纪录 | 高 | 5s | 是 |
| 击杀敌人 | 中 | 2s | 否 |
| 玩家受伤 | 中 | 3s | 否 |
| 低血量 | 中 | 8s | 否 |
| 拾取医疗包 | 低 | 5s | 否 |
| 敌方子弹命中 | 低 | 3s | 否 |

### 4.2 解说队列

```
事件 → CommentaryService.queue(event)
         ↓
    优先级排序 → 冷却检查 → 文本生成 → TTS 播放
         ↓
    播放中若有更高优先级事件 → 中断当前播放
```

## 五、架构方案

### 5.1 新增文件

```
game/CommentaryService.js    — 解说服务（事件收集、优先级、队列、TTS）
game/CommentaryConfig.js     — 配置管理（API Key、解说风格、TTS 设置）
```

### 5.2 改动文件

| 文件 | 改动 |
|------|------|
| `game/GameScene.js` | 在 update() 各事件点调用 commentary.queue() |
| `game/Game.js` | 在射击命中点调用 commentary.queue() |
| `Player.js` | 在 takeDamage() / pickupItems() 调用 commentary.queue() |
| `raycasting.html` | 加载新 JS 文件；新增设置面板 UI |
| `index.js` | 初始化 CommentaryService |

### 5.3 CommentaryService 接口设计

```js
class CommentaryService {
    constructor()
    queue(eventType, context)   // 将事件加入队列
    update(dt)                  // 每帧调用，处理队列
    setEnabled(on)              // 开关解说
    setConfig(config)           // 更新配置
}
```

### 5.4 新增 UI

在 HTML 页面添加一个简洁的设置区域：
- API Key 输入框
- API Endpoint 输入框（默认 OpenAI  compatible）
- 解说风格选择（电竞/冷静/幽默）
- TTS 开关
- 解说音量

放在 `.hint` 区域下方或作为一个可折叠面板。

## 六、技术和风险点

1. **SpeechSynthesis 兼容性**：需检测浏览器支持，不支持时降级为屏幕文字显示
2. **中文语音可用性**：需检测 `zh-CN` 语音是否存在，不存在时提示用户
3. **LLM 延迟**：API 调用 1-3 秒延迟，解说不能实时到毫秒级，可接受
4. **TTS 播放冲突**：同一时间只能播一条，需要队列管理 + 可中断机制
5. **API 费用**：高频事件用模板避免频繁调用，降低费用
6. **CORS**：直接调 OpenAI API 可能有跨域问题，需要用户使用代理或兼容端点
