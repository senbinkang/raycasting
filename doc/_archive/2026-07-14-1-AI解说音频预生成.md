# 2026-07-14 — AI 解说音频预生成

## 一、需求/问题

AI 解说当前每次触发都实时调用 MiMo API 做语音克隆，延迟 2-8 秒，声音出来时事件已经过了。同时语音样本需要用户手动上传，体验不好。需要预先生成好模板音频并嵌入代码，实现即时播放，且兼容 file:// 和 HTTP 双协议。

## 二、做了什么

- 语音样本嵌入代码（`assets/yuqian_voice_sample.wav` → base64 写入 `game/CommentaryVoiceSample.js`），涉及文件：`game/CommentaryVoiceSample.js`
- MiMo 批量预生成 25 条模板音频并嵌入代码，涉及文件：`scripts/generate_audio_cache.mjs`、`game/CommentaryAudioCache.js`
- 重构 CommentaryService 播放流程：模板事件走缓存即时播放，LLM 事件 MiMo 失败自动降级浏览器 TTS，涉及文件：`game/CommentaryService.js`
- 简化 HTML UI：去掉语音上传控件，语音状态显示"已内置（于谦）"，涉及文件：`raycasting.html`
- 语音样本归类：从 `doc/_active/` 移入 `assets/`

## 三、关键决策 / 踩过的坑

- **file:// 兼容性**：`file://` 协议下无法 fetch 外部文件，唯一兼容方案是把所有音频 base64 嵌入 JS 文件通过 `<script>` 加载。代价是 JS 体积增大到 ~5.4MB，但一次加载后浏览器缓存，后续瞬时完成。
- **音频缓存键用文本本身**：`{ "漂亮！下一个！": "base64..." }`，模板随机选中文本后直接 O(1) 查找，无需额外映射。
- **预生成 25/25 全部成功**：MiMo API 响应稳定，未遇到限流或超时。
- **localStorage 仍支持覆盖**：用户如果自己上传语音样本（存 localStorage），会覆盖默认值。但模板音频缓存仍用于谦声音生成的结果——用户自定义声音后模板事件仍播于谦音频，LLM 事件用自定义声音。
