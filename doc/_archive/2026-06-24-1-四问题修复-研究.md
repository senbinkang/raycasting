# 2026-06-24 — 四问题修复 研究

## 1. 玩家被敌人阻挡

**现状**：`Player.js:187-198` `_collidesBlockingSprite()` 对所有 `isBlocking=true` 的精灵做碰撞检测。`Sprite.js:32-36` 中敌人默认 `isBlocking=true`，因此敌人在 `tryMove()` 的 `canMoveX/canMoveY` 中会阻挡玩家。

**根因**：设计上敌人物体与玩家有碰撞，但用户要求玩家可穿过敌人。

**修复点**：`Player.js` `_collidesBlockingSprite()` 中排除 `type === 'enemy'` 的精灵。

## 2. 墙面碰撞

**现状**：`Player.js:133-158` `tryMove()` 使用分轴原子化 + 三点检测（center, center±vr, vr=0.24）。`collisionRadius=0.4`。`cellIsEmpty()` 检查 worldMap 是否为 0 或门已开。

**潜在问题**：三点检测对 0.4 半径的圆覆盖有死角——对角墙角处可能滑入。例如从空地斜向墙角移动时，X/Y 轴分别检测的三个点可能都落在空地上，但实际圆形玩家已经嵌入墙角。

**修复方向**：多用几个采样点或直接检测目标位置所在的格及其相邻格。

## 3. 敌人全灭后重新生成

**现状**：`GameScene.js:126-131` 检测所有敌人死亡后进入 `win` 状态（通关画面）。无重新生成逻辑。

**修复点**：
- 删除通关检测中的 win 跳转，改为调用新方法 `_respawnEnemies()`
- `_respawnEnemies()`：扫描 `_findEmptyCells()` 获取所有空地，随机选 4 个位置（排除玩家附近 2 格），生成新敌人
- 通关门槛改为"累计消灭 N 波敌人"或保留通关条件（全部消灭后显示胜利）

## 4. 玩家初始位置

**现状**：`Player.js:23` `this.position = new Vec(1.5, 1.5)`，然后 `_findStartPosition()` 从候选列表找第一个空地。朝向 `dirX=1.0, dirY=0.0`（朝右）。

**修复点**：
- 初始位置改为地图中央（20×20 地图中央 = (10, 10) 即 `new Vec(10.5, 10.5)`）
- 朝向改为上方：`dirX=0.0, dirY=-1.0`，`planeX=0.66, planeY=0.0`
- `_findStartPosition()` 候选列表同步更新
