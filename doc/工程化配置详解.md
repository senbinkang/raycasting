## 二、项目基础配置

### 2.1 package.json

**文件用途**：项目的核心配置文件，定义项目元数据、依赖关系和可执行脚本。

**关键配置项详解**：

```json
{
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write .",
    "test": "vitest",
    "test:run": "vitest run",
    "test:coverage": "vitest run --coverage",
    "prepare": "husky"
  },
  "lint-staged": {
    "*.{js,jsx}": ["eslint --fix", "prettier --write"],
    "*.{css,html}": ["prettier --write"]
  }
}
```

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `"type": "module"` | 将项目声明为 ES Module 模块 | 允许使用 `import/export` 语法，无需 Babel 转换 |
| `"dev": "vite"` | 启动开发服务器 | 运行 `npm run dev` 启动 Vite 开发服务器，支持热更新 |
| `"build": "vite build"` | 生产构建 | 运行 `npm run build` 将代码打包到 `dist/` 目录 |
| `"preview": "vite preview"` | 预览构建结果 | 在本地启动服务器预览 `dist/` 内容 |
| `"lint": "eslint ."` | 代码检查 | 运行 ESLint 检查所有 JavaScript 文件 |
| `"lint:fix": "eslint . --fix"` | 自动修复 | 自动修复可修复的 ESLint 问题 |
| `"format": "prettier --write ."` | 格式化代码 | 用 Prettier 格式化所有文件 |
| `"test": "vitest"` | 测试（监听模式） | 启动 Vitest 并监听文件变化 |
| `"test:run": "vitest run"` | 测试（单次运行） | 运行一次测试套件 |
| `"test:coverage": "vitest run --coverage"` | 测试覆盖率 | 生成测试覆盖率报告 |
| `"prepare": "husky"` | 安装后自动执行 | npm install 后自动初始化 Husky |
| `"lint-staged"` | 暂存文件处理规则 | 定义提交前对暂存文件的处理流程 |

**工作流角色**：`package.json` 是整个工程化体系的"指挥中心"，所有工具的执行入口都通过 `scripts` 定义。`lint-staged` 配置与 Husky 协作，实现提交前的代码质量保障。

### 2.2 jsconfig.json

**文件用途**：为 VS Code 等 IDE 提供 JavaScript 项目的智能提示和路径解析配置。

**关键配置项详解**：

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  },
  "include": ["src/**/*"]
}
```

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `"baseUrl": "."` | 路径解析的基准目录 | 以项目根目录为基准 |
| `"@/*": ["src/*"]` | 路径别名映射 | 将 `@/` 映射到 `src/` 目录 |
| `"include": ["src/**/*"]` | 包含的文件范围 | IDE 只对 `src/` 目录下的文件提供智能提示 |

**工作流角色**：`jsconfig.json` 主要服务于开发体验，让开发者在 IDE 中可以使用 `import { Vec } from '@/engine/utils/Vec.js'` 这样简洁的路径引用，同时获得完整的代码补全和导航支持。

**注意**：此配置仅影响 IDE 行为，Vite 的路径别名需要在 `vite.config.js` 中单独配置才能在构建时生效。

## 三、构建工具配置

### 3.1 vite.config.js

**文件用途**：Vite 构建工具的核心配置文件，控制开发服务器、生产构建和测试框架的行为。

**关键配置项详解**：

```javascript
import { defineConfig } from 'vite'
import path from 'path'
import { fileURLToPath, URL } from 'node:url'

const __dirname = path.dirname(fileURLToPath(import.meta.url))

export default defineConfig({
  root: 'src',
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
  build: {
    outDir: '../dist',
    emptyOutDir: true,
    rollupOptions: {
      input: {
        main: path.resolve(__dirname, 'src/index.html'),
      },
    },
  },
  server: {
    port: 3000,
    open: true,
  },
  test: {
    globals: true,
    environment: 'jsdom',
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html'],
    },
    include: ['../tests/**/*.test.js'],
  },
})
```

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `root: 'src'` | 项目根目录 | 将 `src/` 设为 Vite 的工作目录，所有路径解析基于此 |
| `resolve.alias` | 模块解析别名 | 配置 `@/` 指向 `src/`，与 `jsconfig.json` 保持一致 |
| `build.outDir` | 构建输出目录 | 将构建产物输出到项目根目录下的 `dist/` |
| `build.emptyOutDir` | 清空输出目录 | 每次构建前清空 `dist/` 目录 |
| `build.rollupOptions.input` | 入口文件 | 指定 `src/index.html` 作为构建入口 |
| `server.port` | 开发服务器端口 | 默认监听 3000 端口 |
| `server.open` | 自动打开浏览器 | 启动开发服务器后自动打开浏览器 |
| `test.globals` | 全局测试 API | 测试文件中可直接使用 `describe`, `it`, `expect` |
| `test.environment` | 测试环境 | 使用 `jsdom` 模拟浏览器环境 |
| `test.coverage.provider` | 覆盖率工具 | 使用 V8 引擎内置的覆盖率收集 |
| `test.coverage.reporter` | 覆盖率报告格式 | 生成文本、JSON、HTML 三种格式报告 |
| `test.include` | 测试文件范围 | 指定测试文件的查找路径 |

**工作流角色**：`vite.config.js` 是构建流程的核心配置，同时集成了 Vitest 的配置，实现了构建工具与测试框架的统一配置管理。

**设计亮点**：
1. `root: 'src'` 将源代码与配置文件分离，保持项目根目录整洁
2. `outDir: '../dist'` 将构建产物输出到项目根目录，便于部署
3. Vite 与 Vitest 共享配置，减少配置文件数量

## 四、代码质量与规范配置

### 4.1 eslint.config.js

**文件用途**：ESLint 的配置文件（扁平配置格式），定义代码质量检查规则和全局变量。

> **重要**：本项目使用 ESLint v10+ 的扁平配置格式 (`eslint.config.js`)，而非旧版的 `.eslintrc.cjs` 格式。扁平配置使用 ES Module 语法，配置结构更清晰、更灵活。

**关键配置项详解**：

```javascript
import globals from 'globals'
import js from '@eslint/js'

export default [
    js.configs.recommended,
    {
        ignores: [
            'Background.js',
            'Player.js',
            'Screen.js',
            'Sprite.js',
            'SpriteManager.js',
            'Weapon.js',
            'AudioManager.js',
            'CommentaryAudioCache.js',
            'CommentaryService.js',
            'CommentaryVoiceSample.js',
            'OverlayScreen.js',
            'Game.js',
            'GameScene.js',
            'TextureManager.js',
            'utils.js',
            'index.js',
            'textures.js',
            'raycasting.html',
            'game/',
            'scripts/',
            'vite.config.js',
            'node_modules/',
            'dist/',
            'docs/',
            '.husky/',
            '.vite/',
            'coverage/',
            '*.config.cjs',
        ],
    },
    {
        files: ['src/**/*.js'],
        languageOptions: {
            ecmaVersion: 'latest',
            sourceType: 'module',
            globals: {
                ...globals.browser,
                ...globals.node,
                speechSynthesis: true,
                SpeechSynthesisUtterance: true,
                AudioContext: true,
                fetch: true,
                AbortController: true,
            },
        },
        rules: {
            'no-unused-vars': ['warn', { vars: 'all', args: 'after-used', ignoreRestSiblings: true, caughtErrors: 'none' }],
            'no-undef': 'warn',
            'prefer-const': 'warn',
            'arrow-parens': ['warn', 'always'],
            'curly': ['warn', 'all'],
            'eqeqeq': ['warn', 'always'],
            'no-console': ['warn', { allow: ['error', 'warn', 'info'] }],
            'semi': ['warn', 'never'],
            'quotes': ['warn', 'single'],
            'no-trailing-spaces': 'warn',
            'eol-last': 'warn',
            'comma-dangle': ['warn', { arrays: 'always-multiline', objects: 'always-multiline', imports: 'always-multiline', exports: 'always-multiline', functions: 'never' }],
        },
    },
]
```

**配置结构说明**：

扁平配置是一个数组，每个元素是一个配置对象，按顺序应用：

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `js.configs.recommended` | 官方推荐规则 | 使用 ESLint 官方推荐的规则集 |
| `ignores` | 忽略文件列表 | 指定不进行检查的文件和目录 |
| `files: ['src/**/*.js']` | 作用范围 | 仅对 `src/` 目录下的 JavaScript 文件应用规则 |
| `languageOptions.ecmaVersion` | ECMAScript 版本 | 设置为 `latest` 支持所有现代语法 |
| `languageOptions.sourceType` | 模块类型 | 设置为 `module` 支持 ES Module 语法 |
| `languageOptions.globals` | 全局变量 | 声明浏览器和 Node.js 全局变量 |

**rules 规则详解**：

| 规则 | 级别 | 含义 |
|-----|------|------|
| `no-unused-vars` | warn | 检测未使用的变量，避免死代码 |
| `no-undef` | warn | 检测未定义的变量，避免拼写错误 |
| `prefer-const` | warn | 建议使用 `const` 替代 `let`（当变量不变时） |
| `arrow-parens` | warn | 箭头函数参数必须加括号 |
| `curly` | warn | 所有控制语句必须使用花括号 |
| `eqeqeq` | warn | 强制使用 `===` 和 `!==` 而非 `==` 和 `!=` |
| `no-console` | warn | 禁止 `console.log`，但允许 `error`, `warn`, `info` |
| `semi` | warn | 禁止行尾分号 |
| `quotes` | warn | 使用单引号而非双引号 |
| `no-trailing-spaces` | warn | 禁止行尾空白 |
| `eol-last` | warn | 文件末尾必须有空行 |
| `comma-dangle` | warn | 对象和数组最后一个元素加逗号 |

**globals 配置的必要性**：

本项目大量使用浏览器 API（如 `AudioContext`, `speechSynthesis`, `localStorage`），这些 API 在 ESLint 默认规则下会被标记为"未定义"。通过 `globals` 配置声明这些全局变量为合法，避免误报。

**工作流角色**：ESLint 在开发阶段提供实时代码质量反馈，在提交阶段配合 lint-staged 自动修复问题，在 CI 阶段作为质量门禁。

### 4.2 .prettierrc

**文件用途**：Prettier 的配置文件，定义代码格式化规则。

**关键配置项详解**：

```json
{
  "semi": false,
  "singleQuote": true,
  "trailingComma": "es5",
  "printWidth": 120,
  "tabWidth": 4,
  "endOfLine": "lf"
}
```

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `"semi": false` | 不添加行尾分号 | 与 ESLint 的 `semi: never` 规则一致 |
| `"singleQuote": true` | 使用单引号 | 与 ESLint 的 `quotes: single` 规则一致 |
| `"trailingComma": "es5"` | ES5 风格尾逗号 | 对象和数组最后一个元素加逗号 |
| `"printWidth": 120` | 行宽限制 | 超过 120 字符自动换行 |
| `"tabWidth": 4` | 缩进宽度 | 使用 4 个空格缩进 |
| `"endOfLine": "lf"` | 换行符 | 使用 LF（Unix 风格）换行符 |

**与 ESLint 的协作关系**：

Prettier 负责代码格式（缩进、换行、引号等），ESLint 负责代码质量（变量使用、语法正确性等）。两者规则需要保持一致，避免冲突。本项目中：
- `semi` 和 `singleQuote` 在两个配置中保持一致
- `trailingComma: "es5"` 与 ESLint 的 `comma-dangle: es5` 一致

**工作流角色**：Prettier 在开发阶段自动格式化代码，在提交阶段配合 lint-staged 确保提交代码格式统一。

## 五、Git 提交规范配置

### 5.1 .husky/pre-commit

**文件用途**：Husky 的提交前钩子脚本，在每次 git commit 前执行。

**脚本内容**：

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx lint-staged
```

| 命令 | 含义 | 作用 |
|------|------|------|
| `#!/usr/bin/env sh` | 指定脚本解释器 | 使用 POSIX shell 执行 |
| `. "$(dirname -- "$0")/_/husky.sh"` | 加载 Husky 核心脚本 | 提供 Husky 的运行时环境 |
| `npx lint-staged` | 执行 lint-staged | 对暂存文件进行检查和修复 |

**工作流角色**：`pre-commit` 钩子是代码质量的第一道防线，确保只有通过检查的代码才能提交到版本库。

**工作流程**：
1. 用户执行 `git commit`
2. Git 触发 `pre-commit` 钩子
3. Husky 执行 `.husky/pre-commit` 脚本
4. 脚本调用 `lint-staged` 处理暂存文件
5. 如果所有检查通过，提交成功；否则提交失败

### 5.2 commitlint.config.cjs

**文件用途**：Commitlint 的配置文件，验证 git commit 信息是否符合规范。

**配置内容**：

```javascript
module.exports = {
    extends: ['@commitlint/config-conventional'],
}
```

| 配置项 | 含义 | 作用 |
|-------|------|------|
| `extends: ['@commitlint/config-conventional']` | 继承 Conventional Commits 规范 | 使用行业标准的提交信息格式 |

**Conventional Commits 规范格式**：

```
<type>(<scope>): <description>

<body>

<footer>
```

**常用 type 值**：

| type | 含义 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(engine): 添加碰撞检测` |
| `fix` | 修复 Bug | `fix(game): 修复敌人不攻击` |
| `refactor` | 代码重构 | `refactor(audio): 重构音频管理器` |
| `docs` | 文档更新 | `docs(readme): 更新安装说明` |
| `test` | 测试代码 | `test(utils): 添加 Vec 测试` |
| `chore` | 构建/工具相关 | `chore(deps): 更新依赖` |
| `style` | 代码格式 | `style: 格式化代码` |

**工作流角色**：Commitlint 确保团队成员的提交信息格式统一，便于后续的版本发布和 CHANGELOG 自动生成。

```
tests/
```

**测试命令**：

| 命令 | 用途 |
|------|------|

| `npm run test:run` | 运行一次测试套件 |
| `npm run test:coverage` | 运行测试并生成覆盖率报告 |

**工作流角色**：Vitest 在开发阶段提供快速的测试反馈，在 CI 阶段作为质量门禁确保代码变更不会破坏现有功能。

## 七、CI/CD 配置

### 7.1 .github/workflows/ci.yml

**文件用途**：GitHub Actions 的工作流配置文件，定义持续集成和持续部署流程。

**关键配置项详解**：

```yaml
name: CI/CD

on:
  push:
    branches:
      - main
      - v4-*
  pull_request:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
```

## 八、渐进式模块化迁移策略

### 8.1 bootstrap.js 的设计模式

**文件路径**：[src/bootstrap.js](file:///Users/kangsenbin/Downloads/ai-work/games/raycasting/src/bootstrap.js)

**内容**：

```javascript
import './audio/CommentaryVoiceSample.js'
import './audio/CommentaryAudioCache.js'
import './audio/AudioManager.js'
import './audio/CommentaryService.js'
```

**设计意图**：

由于 `CommentaryService` 和 `AudioManager` 模块使用了 `window` 全局挂载的方式（如 `window.commentaryService = new CommentaryService()`），且其他模块（如 `GameScene.js`）通过 `window` 对象访问这些服务，直接改为 ES Module 导出会导致大量代码修改。

**渐进式迁移策略**：

1. **第一步**：保持全局挂载方式，通过 `bootstrap.js` 统一初始化顺序
2. **第二步**：在新代码中使用 ES Module `import` 方式引入
3. **第三步**：逐步改造旧代码，移除 `window` 全局依赖

**当前架构中的位置**：

```
main.js
    │
    ├── bootstrap.js          (初始化全局服务)
    │       ├── CommentaryVoiceSample.js
    │       ├── CommentaryAudioCache.js
    │       ├── AudioManager.js          → window.audioManager
    │       └── CommentaryService.js     → window.commentaryService
    │
    ├── Game.js
    └── GameScene.js
            ├── Player.js
            ├── Background.js
```

## 十、常见问题与解决方案

### 10.1 ESLint 报 "window is not defined"

**问题**：ESLint 检测到 `window` 是未定义变量。

**解决方案**：在 `.eslintrc.cjs` 的 `globals` 配置中添加 `window: true`。

### 10.2 路径别名 `@/` 在 IDE 中无法解析

**问题**：VS Code 无法识别 `@/` 路径别名。

**解决方案**：确保 `jsconfig.json` 中正确配置了 `paths` 映射。

### 10.3 测试报错 "Cannot find dependency 'jsdom'"

**问题**：Vitest 需要 jsdom 环境但未安装。

**解决方案**：运行 `npm install -D jsdom`。

### 10.4 构建时报错 "chunk size exceeds 500KB"

**问题**：生产构建产物过大。

**解决方案**：当前为开发阶段警告，生产环境可考虑：
1. 使用动态 `import()` 进行代码分割
2. 配置 `build.chunkSizeWarningLimit` 调整警告阈值

### 10.5 Husky 钩子不生效

**问题**：提交代码时未触发 lint-staged。

**解决方案**：
1. 确保 `.husky/pre-commit` 文件有执行权限（`chmod +x .husky/pre-commit`）
2. 确保 `node_modules/.husky/_/husky.sh` 文件存在
3. 运行 `npm run prepare` 重新初始化 Husky
