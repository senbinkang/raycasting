# 2026-06-17 — 第二轮 6 个问题根因分析

## 一、背景

上一轮修复了碰撞半径 + 射击命中 + 血条 + 开始画面，本轮继续深入。

## 二、逐项根因

### Bug 1：墙体仍可穿过

**根因**：上次加的三对角点检测（`position.y ± r`）矫枉过正——反而导致墙角场景下，上方/下方检测点跨入隔壁墙格，而中心检测点却在空地，三个点用 AND 连接时理应正确阻止。但实际问题出在**另一侧**：

当玩家沿墙滑行时，垂直于墙方向的速度分量为 0（被挡住），但平行于墙的速度一直在累积。如果玩家稍微朝墙方向偏转，`dx * step` 会产生一个微小的穿墙分量。此时 `Math.sign(dx)` 为正，checkX 为 `newX + r`。但如果 `dx` 非常小（比如 0.001），`Math.sign(dx)` 仍为 +1，而 `newX = position.x + 0.001 * step`。checkX = `position.x + 微小量 + r`。如果 `position.x + r` 已经逼近墙边界，这个微小增量可能恰好越界。

但更可能的原因是：**分轴检测本身的缺陷**。X 轴先检测，如果 X 轴通过（因为 checkX 恰好落在空地），position.x 更新。然后 Y 轴检测使用新的 position.x。这导致先发生的轴向移动"绑架"了后发生的轴向检测，使其在一个不同的 X 位置做判断。

**修复方向**：
- 把分轴检测改为先记录两轴结果，再一起应用（原子化）
- 或者增大 collisionRadius 到 0.4，留出更多安全余量
- 增加事后修正：如果移动后的位置落入墙格，回退到上一帧位置

### Bug 2：墙面间有缝隙

**根因**（`Screen.js:336-343` `_drawWall()`）：

```javascript
let wallX = (side === 0) ? posY + perpDist * rayDirY : posX + perpDist * rayDirX
wallX -= Math.floor(wallX)
let texX = Math.floor(wallX * texSize)
```

在相邻两列射线命中不同墙面时（如墙角转折），`wallX` 在边界处不连续，导致纹理采样跳变，产生竖直缝隙。这是 raycasting 的固有浮点精度问题。

此外 `drawStart`/`drawEnd` 使用 `Math.floor`，相邻列间可能有 ±1 像素的高度差，形成水平缝隙。

**修复方向**：
- 对相邻列的 `drawStart`/`drawEnd` 做平滑（取相邻列平均值）
- 或者将 `drawStart` 向上、`drawEnd` 向下各扩展 1 像素（简单粗暴但有效）

### Bug 3：血条不显示 / 不明显

上一轮已加了血条（`Game.js:211-227`），但可能存在：
- 用户没看到（位置在左下角偏小）
- 或者在不同状态下没渲染（只在 `state === 'playing'` 时绘制 HUD）

**修复方向**：确认血条可见性；把数字加大加粗，确保在复杂背景下可读。

---

### Bug 4：敌人不能攻击玩家

**根因**（`Sprite.js:78`）：敌人到达距离 < 0.8 后 `return` 停止移动，但不造成任何伤害。没有接触伤害逻辑。

**修复方向**：在 `SpriteManager.update()` 或 `Sprite.update()` 中加接触伤害检测——敌人距玩家 < 某阈值时，按时间扣血（如每秒 20 点）。加受伤无敌时间（invincibility frames）防止每帧连续扣血。

---

### Bug 5：地图太小

当前地图 10×10，外圈红墙占满边界，内部可玩区域只有 8×8。需要扩展到更大尺寸（建议 20×20），增加更多房间和走廊。

---

### Bug 6：敌人重叠

**根因**：`SpriteManager.update()` 中每个敌人独立 AI，无敌人间碰撞检测。两个敌人追玩家时会走到同一位置。

**修复方向**：在 `SpriteManager.update()` 中，每帧对所有敌人两两做距离检测，距离 < `radius*2` 时互相推开（分离力）。
